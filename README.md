# 실습2앱 실행 안내

이 폴더의 `index.html`을 더블클릭하세요. 설치나 서버 없이 실행하며, 함께 있는 `style.css`, `core.js`, `app.js`를 상대 경로로 읽습니다. 폴더를 다른 곳으로 옮길 때는 내부 파일을 함께 옮겨 주세요.

기준 원본은 상위 폴더의 `실습2.html`입니다. 원본과 기존 `실습앱/`은 수정하지 않았습니다.

## 파일 역할

| 파일 | 역할 |
|---|---|
| `index.html` | 기존 화면 구조. `./style.css`, `./core.js`, `./app.js`를 읽음 |
| `style.css` | 원본의 스타일 전체. 휴대폰 배치 포함 |
| `app.js` | 필터 선택, 화면 갱신, 입력 창, 저장 결과·오류 안내 |
| `core.js` | 계산, 값 검사, 가상 샘플 8개, 브라우저 읽기·저장 기능 |
| `data/kpi.json` | 가져오기와 원본 비교용 JSON 사본 |
| `data/kpi.csv` | 가져오기와 원본 비교용 UTF-8 CSV 사본. 한글 인식을 위한 BOM 포함 |
| `tests.cjs` | 필터·계산·저장·사본 일치 검증 |

## 샘플 데이터 사용

처음 실행할 때 `core.js`의 내장 샘플을 사용합니다. 사용자가 명시적으로 저장한 브라우저 데이터가 있으면 그것을 먼저 읽습니다. JSON·CSV를 자동으로 읽거나 `fetch`로 요청하지 않으므로 파일 직접 열기에서 발생하는 `fetch` 실패가 없습니다.

JSON·CSV는 **가져오기와 원본 비교용 사본**입니다. 다른 도구의 가져오기 기능에 넣거나 원본 값과 비교하는 용도입니다. 이 앱에 파일 가져오기 화면을 새로 추가한 것은 아닙니다. 사본을 수정해도 화면이나 브라우저 저장값이 자동으로 바뀌지 않으며, 화면에서 저장해도 사본은 바뀌지 않습니다.

사본의 공통 필드는 `id, month, department, metric, target, actual, evidence`입니다. 금액 단위는 만원입니다. JSON의 목표·실적은 숫자이고, CSV를 가져오는 도구에서는 해당 열을 숫자로 해석해야 합니다.

저장 방식과 키(`kpi-dashboard.practice.sample.v1`)는 원본과 같습니다. 같은 브라우저의 같은 저장소 영역에서 열면 원본과 저장값을 공유할 수 있으며, `file://` 파일별 저장소 구분은 브라우저에 따라 다릅니다. 최초 조회 때 샘플을 자동 저장하지 않습니다. 입력·수정 후 저장 단추를 누를 때만 브라우저에 저장합니다. 실제 DB에는 연결하지 않습니다.

## 유지한 계산과 화면 동작

- 월·부서 필터를 함께 적용하고 합계·그래프·근거표를 갱신합니다.
- 달성률 = 실적 합계 ÷ 목표 합계 × 100. 목표 합계가 0이면 ‘목표 미설정’입니다.
- 조회 결과가 없으면 빈 상태를, 읽기 실패 시 오류 패널을 표시합니다.
- 기존 입력·수정, 샘플 모드 표시, 휴대폰용 스타일을 유지했습니다.

## 실제 화면 확인과 추가 설계의 구분

**실제 화면에서 확인한 것:** 이번 작업에서는 브라우저를 통한 시각·조작 검수를 하지 않았습니다. 따라서 ‘같은 화면을 실제로 보아 확인했다’고 보고하지 않습니다. 이전 검수에서도 브라우저 주소를 확인하지 못해 화면 검수가 중단된 이력이 있습니다.

**파일 대조와 코드 검증으로 확인한 것:** 원본 HTML의 화면 구조와 CSS가 그대로 유지되었으며, 화면 동작 코드는 `KpiDomain`·`KpiData` 참조를 `KpiCore`로 연결하는 부분만 변경했습니다. 분리된 JavaScript 문법 검사 및 자동 검증 14개를 통과했습니다. 10월 목표 36,000만원·실적 36,500만원·달성률 101.4%, 목표 0, 필터 교집합, 소수 금액, 빈 데이터, 저장 실패와 손상 자료 보존, JSON·CSV 사본 일치 등을 확인했습니다.

**이번 요청에 따른 추가 설계:** 파일 역할 분리, 통합된 `KpiCore` 연결 지점, 상대 경로 로딩, 샘플 사본 2종, 안내·검증 파일입니다. 새로운 화면 기능이나 실제 DB 연결 기능을 추가한 것은 아닙니다. 향후 Supabase 연결 시 `app.js`의 저장소 생성 지점에서 `list()`·`save(record)`를 제공하는 저장소로 교체할 수 있으며, 실제 인증·권한·테이블은 미설계 상태입니다.

## 검증 실행과 미확인 항목

Node.js가 있는 환경에서 이 폴더의 터미널에서 `node --test tests.cjs`를 실행하면 됩니다.

실제 브라우저의 더블클릭 실행, 휴대폰 조작·잘림, 브라우저별 저장 제한, 외부 도구에서의 CSV 가져오기는 미확인입니다. 다음 확인 순서는 ① `index.html`을 열어 화면 보기 ② 월·부서 필터와 목표 0 표시 확인 ③ 휴대폰에서 입력·저장 확인입니다.

외부 배포·업로드·커밋·실제 DB 변경은 수행하지 않았습니다.
